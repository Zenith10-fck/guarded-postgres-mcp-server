The problem

Connecting Claude to a company's live Postgres database is one of the most-requested AI automation jobs — and one of the most dangerous. The moment Claude can execute SQL, three things can go wrong, all quietly:

  • Destruction. A confused model, or a pasted "helpful" query, runs DROP TABLE, DELETE, or a stacked-statement injection — data gone.
  • Leakage. Claude returns a full column of emails or phone numbers because nobody told it those were off-limits.
  • Silent wrong answers. A query returns a truncated or wrong-shaped result, Claude reports it as fact, and a decision gets made on bad numbers.

Most "connect Claude to your DB" demos ignore all three because they demo on the happy path. This build is designed against the failure path.

What I built

An MCP server that gives Claude governed Postgres access. Every call passes through an explicit chain of guards before it ever reaches the database.

Claude Desktop / API ──MCP (stdio)──▶ Guarded MCP Server (Python) ──▶ Postgres │ ▲ Auth → Rate-limit → Schema-validate → SQL-guard → │ PII-redact → Audit-log least-privilege role │ policy.yaml (single source of truth: which tables/columns, read vs write, row limits, which columns are PII)

Key decision: every guardrail is driven by one policy.yaml file, not hard-coded. To point this at a different client's database, you edit that file — not the code. That's what makes it a reusable product, not a one-off script.

The reliability layer — defense in depth

Safety here isn't one wall; it's independent layers that would each have to fail:

  • Application SQL guard. query is parsed into a syntax tree with sqlglot and rejected unless it's exactly one read-only SELECT — catching a DELETE smuggled inside a CTE.
  • Least-privilege DB roles. Never a superuser. Reads use a SELECT-only role; writes use a separate role that can't DELETE/DROP/ALTER anything. A Python-guard bug still can't destroy data — the database itself refuses.
  • Policy-driven PII redaction on every result.
  • Dry-run writes — nothing changes until an explicit confirm=true.
  • Structured errors — {error_code, message, hint}, never a stack trace or a silent empty result.
  • Full audit log — every call recorded to an append-only trail.

Point it at your database — about 15 minutes

  • docker compose up -d starts a demo Postgres, or set DATABASE_URL to your own.
  • Copy policy.example.yaml → policy.yaml; list your tables, columns, writable ones, and PII ones.
  • Create the two least-privilege roles (SQL provided).
  • Register the server in Claude Desktop (one JSON block, provided).
  • Ask a business question — watch Claude query safely, then refuse a DROP TABLE with a clean explained error.
